# Google 스타일 작업 브라우저 — 내 PC의 Claude Code를 검색창처럼 쓰는 웹 UI

검색 페이지처럼 생긴 로컬 웹 화면에서 작업을 입력하면, 이 PC의 Claude Code가 지정한 프로젝트에서 코딩합니다. 진행 상황과 결과는 검색 결과 페이지 형태로 실시간으로 보여 줍니다.

- **홈**: Google 스타일 검색창, 작업 폴더 선택, 해당 폴더에서 Claude Code가 제공하는 모델 목록, 최근 대화 바로가기, 세션 이어가기
- **결과 페이지**: 파란 제목과 짧은 설명, 더보기로 펼치는 전체 답변과 작업 과정, 우측 정보 패널
- 텍스트 입력과 이미지 붙여넣기·드래그 지원
- 대화 하나에 Claude 세션 하나가 연결됩니다. 세션 ID는 SQLite에 저장되므로 새로고침이나 서버 재시작 뒤에도 이어서 작업할 수 있습니다.

구성: TypeScript · Node.js `http` · [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) `0.3.312` · better-sqlite3 · 순수 HTML/CSS/JS (외부 CDN 없음)

---

## 1. 준비물

- Node.js 20.12 이상 (22 권장)
- **Claude Code 인증**: Agent SDK는 이 PC의 Claude Code 실행 파일을 사용합니다.
  - 공식 문서는 Agent SDK 기반 앱에 **API 키 인증**(`ANTHROPIC_API_KEY`)을 권장합니다. claude.ai 로그인이나 사용량 한도를 서드파티 제품에 제공하는 것은 사전 승인 없이는 허용되지 않습니다 ([Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)).
  - API 키는 셸 환경변수나 `.env`에 `ANTHROPIC_API_KEY=...`로 넣으세요. 봇이 키를 로그나 화면에 출력하지 않도록 가려집니다.

## 2. 설치

```bash
npm install
cp .env.example .env
cp projects.example.json projects.json
```

### `.env` (필수 항목)

```ini
WEB_ACCESS_TOKEN=여기에-긴-랜덤-문자열      # openssl rand -hex 24
WORKSPACE_ROOT=/Users/me/work              # 모든 프로젝트는 이 안에 있어야 함
PERMISSION_MODE=bypassPermissions          # 자동 실행. default | acceptEdits | plan 도 가능
```

나머지 옵션은 `.env.example`의 주석을 참고하세요.

### `projects.json`

```json
{
  "projects": {
    "my-api": "my-api",
    "portfolio": "portfolio-site"
  }
}
```

경로는 `WORKSPACE_ROOT` 기준의 상대 경로나 절대 경로로 씁니다. 심볼릭 링크를 따라갔을 때 `WORKSPACE_ROOT` 밖으로 나가는 경로는 거부됩니다. `.`을 등록하면 작업 폴더 전체를 선택할 수 있습니다. 앱 설정 폴더는 파일 도구에서 차단하며, 해당 폴더를 포함하는 광역 검색도 차단합니다.

## 3. 실행

```bash
npm run build && npm start      # 운영
npm run dev                     # 개발 (tsx)
```

브라우저에서 `http://127.0.0.1:3939`에 접속한 뒤 `WEB_ACCESS_TOKEN`을 입력합니다. 쿠키는 30일 동안 유지됩니다.
로그인창에는 `WEB_ACCESS_TOKEN=` 뒤의 **값만** 넣으세요. 토큰을 클립보드에 복사하려면 `sed -n 's/^WEB_ACCESS_TOKEN=//p' .env | pbcopy`를 실행합니다. 화면 코드나 `projects.json`을 바꾼 뒤에는 서버를 `Ctrl+C`로 종료하고 다시 시작해야 변경 사항이 반영됩니다.

종료는 `Ctrl+C`(SIGINT/SIGTERM)입니다. 실행 중인 작업을 중단하고, 상태를 기록한 뒤 종료합니다.

## 4. 사용법

| 하고 싶은 것 | 방법 |
|---|---|
| 새 작업 | 홈 검색창에 입력 → Enter (Shift+Enter는 줄바꿈). 오른쪽 칩에서 작업 폴더와 모델 선택 |
| 모델 | 홈에서 Claude Code가 실제 제공하는 모델을 선택합니다. 대화가 시작되면 선택 모델이 저장되어 이후 입력에서도 유지됩니다 |
| 이어서 작업 | 결과 페이지 상단 검색창에 입력 (같은 세션으로 이어감) |
| 이미지 | 붙여넣기 · 드래그 (png/jpeg/gif/webp, 기본 4장·5MB) |
| 자동 실행 | `PERMISSION_MODE=bypassPermissions`로 설정하면 승인 버튼 없이 작업을 진행합니다 |
| 상세 내용 | 답변과 작업 과정의 **더보기**를 누르면 전체 내용과 코드가 표시됩니다 |
| 중지 (`/stop`) | 오른쪽 위 또는 패널의 **중지** 버튼. 실행 중인 작업과 대기 중인 작업을 모두 취소 |
| 상태 (`/status`) | 오른쪽 정보 패널 (프로젝트·세션 ID·상태·최근 작업) |
| 새 세션 (`/new`) | 패널의 **새 세션** 버튼. 이전 세션 ID는 기록에 남음 |
| 세션 이어가기 (`/resume`) | 홈의 **+ 세션 이어가기** 타일. 터미널에서 만든 세션 ID도 연결 가능 |

같은 프로젝트의 작업은 **한 번에 하나씩 순서대로** 실행되고, 다른 프로젝트끼리는 동시에 실행됩니다.

## 5. 보안 설계

- **접근 제어**: 기본적으로 `127.0.0.1`에만 바인딩합니다. 모든 요청에 토큰 로그인 쿠키(HttpOnly, SameSite=Strict)가 필요하고, 로그인 실패는 5분에 5회로 제한됩니다.
- **웹 보안**:
  - CSRF 방지: 변경 요청은 커스텀 헤더와 같은 출처(Origin)일 때만 받습니다.
  - Host 헤더 검사로 DNS 리바인딩을 막습니다.
  - 엄격한 CSP를 적용합니다. 인라인 스크립트·스타일과 외부 리소스를 모두 금지합니다.
  - 마크다운은 먼저 HTML 이스케이프한 뒤 렌더링합니다.
- **권한**:
  - `permissionMode`를 명시합니다. `bypassPermissions`는 사용자 확인 없이 도구를 실행합니다.
  - `default`, `acceptEdits`, `plan` 모드에서는 필요한 도구가 승인 버튼으로 전달됩니다.
- **작업 경로 제한**:
  - 파일 도구(Read/Write/Edit/Glob/Grep/NotebookEdit)의 경로를 심볼릭 링크까지 풀어서 검사합니다.
  - 앱 설정 폴더의 직접 접근과 그 폴더가 포함되는 Glob/Grep 검색을 차단합니다.
  - 프로젝트 밖 접근, 그리고 `.env`, `*.pem`, `*.key`, `id_rsa`, `.ssh/` 같은 인증정보 파일 접근은 **보안 차단** 처리하고 해당 작업을 종료합니다.
- **비밀값 노출 방지**:
  - 자식 프로세스 환경에서 봇 설정값과 "부모 Claude Code 세션에 붙는" 변수(`CLAUDE_CODE_SESSION_ID` 등)를 제거합니다.
  - 화면·DB·로그로 나가는 모든 텍스트에서 환경변수의 비밀값과 흔한 토큰 형식(`sk-ant-…`, GitHub·AWS·Slack 키, 개인키 등)을 `[REDACTED]`로 가립니다.

## 6. 예외 처리

| 상황 | 동작 |
|---|---|
| 권한 거절 / 응답 시간 초과 | Claude에게 "중단, 재시도 금지"를 전달(`interrupt`)하고 **그 작업만** 종료합니다. 이유를 표시합니다 |
| 보안 차단 | 훅에서 거부하고 그 작업만 종료합니다. 차단된 경로를 표시합니다 |
| 승인 카드를 표시할 수 없음 | 승인하지 않고 **거절로** 처리합니다 |
| 중지 | 먼저 부드럽게 `interrupt`하고, 15초 안에 끝나지 않으면 강제 `abort`합니다. 대기열의 같은 대화 작업도 취소합니다 |
| 인증 실패 · 결제 문제 · 사용량 한도 · API 과부하 · 최대 턴 · SDK 실행 실패 · 프로세스 크래시 | 유형별 안내를 표시합니다(한도는 재설정 시각 포함). **자동 재시도는 하지 않습니다** |
| 이미지 오류 (형식·크기·개수·손상) | 매직 바이트로 실제 형식을 검사합니다. 실패하면 요청을 받지 않고 이유를 알려 줍니다 |
| 브라우저 연결 끊김 | 작업은 서버에서 계속 진행됩니다. 재연결하면 전체 상태를 다시 받아 표시합니다 |
| 작업이 실패·취소·거절된 경우 | 파일 수정이나 명령이 있었다면 "일부 변경이 남아 있을 수 있음, `git status` 확인"을 안내합니다 |
| 모든 종료 경로 | `finally`에서 프로젝트 잠금 해제, 승인 카드 정리, DB 작업 상태 확정을 항상 수행합니다 |
| 서버 재시작 | 실행·대기 중이던 작업은 `interrupted`로 바꾸고 **자동 재실행하지 않습니다**. 열린 승인 카드는 무효화하고, 대화에 안내를 남깁니다. 세션은 유지됩니다 |
| 세션 재개 실패 | 저장된 세션 ID를 **지우지 않고** 대화를 "재개 불가" 상태로 둡니다. **새 세션** 또는 **세션 다시 확인** 버튼으로만 진행할 수 있습니다 |
| 재개했는데 CLI가 다른 세션 ID로 시작하려 함 | 몰래 새 대화가 되는 것을 막기 위해 즉시 중단하고, 위와 같이 처리합니다 |
| 서버 중복 실행 | SQLite 배타 잠금 때문에 두 번째 인스턴스는 시작하지 않습니다 |
| 처리되지 않은 예외 | 로그만 남기고 서버는 계속 동작합니다 |

## 7. 검증

```bash
npm test          # 모의 SDK 단위 테스트 28개
npm run typecheck
```

단위 테스트 범위:
- 정상 대화, 세션 저장·재개, 재시작 후 재개
- 거절, 시간 초과, 승인, 다른 대화의 승인 토큰 거부
- 보안 차단과 경로 규칙(심볼릭 링크 탈출, `.env`)
- 취소, 응답 없는 SDK의 강제 종료
- 재시작 복구(재실행 없음, 승인 카드 무효화)
- 세션 재개 실패 처리와 세션 ID 바뀜 감지
- 인증 실패, 사용량 한도, 실행 실패, 크래시, 최대 턴
- 출력의 비밀값 가림
- 프로젝트별 순차 실행과 다른 프로젝트 병렬 실행, 대기열 제한
- 이미지 검증, DB 중복 실행 잠금, 자식 환경 정리, 설정 거부
- HTTP 로그인, CSRF, CSP

**실제 Claude Code로 브라우저에서 확인한 결과** (Playwright, haiku 모델):

1. 정상 대화: `add` 버그 수정 요청 → Bash·Edit 승인 → `a - b`가 `a + b`로 고쳐짐
2. 재시작 복구: 승인 대기 중에 서버를 강제 종료 → 재시작 시 작업은 `interrupted`로 바뀌고 안내만 표시, 재실행 없음
3. 세션 재개: 재시작 뒤 "방금 수정한 파일?" → `src/math.js`라고 답함 (같은 세션 ID)
4. 권한 거절: `rm README.md` 거절 → 해당 작업만 종료, 파일은 그대로
5. 보안 차단: `/etc/hostname` 읽기 시도 → 차단되고 작업 종료
6. 취소: 중지 버튼 → 0.5초 안에 정리되고, 바로 다음 요청이 같은 세션으로 실행됨

## 8. 알아둘 점

- **Bash 내용은 경로 검사를 할 수 없습니다.** 자동 실행 모드에서는 Bash 명령도 바로 실행됩니다.
- **Grep 결과 노출 가능성**: 프로젝트 안 일반 파일에 비밀값이 섞여 있으면 Grep 결과에 보일 수 있습니다. 흔한 토큰 형식은 가려지지만 모든 형식을 보장하지는 않습니다.
- **승인 버튼 개수**: `acceptEdits` 모드에서는 프로젝트 안 파일 수정이 자동 승인됩니다. `bypassPermissions` 모드에서는 승인 버튼이 나오지 않습니다.
- **명확화 질문**: Claude의 선택형 질문(`AskUserQuestion`)은 끄고, 일반 답변으로 묻게 했습니다. 그 질문에는 검색창에 답하면 됩니다.
- **세션 저장 위치**: Claude Code가 이 PC의 `~/.claude/projects/` 아래에 저장합니다. 그 기록을 지우면 재개할 수 없고, 화면에서 새 세션으로 안내합니다.
